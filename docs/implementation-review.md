## Findings in severity order

### High · 1 · An unrelated citation can qualify a fabricated assessment for the inbox

An ordinary-mode MSFT run with scripted transport answered a dividend question with **$12.34 per share**. Its sole factual quotation was `120000000` from an SEC revenue cell. The service committed a complete brief with zero calculations and gaps. The validator checks that a factual claim is a substring of a retrieved passage. It checks the conclusion and changes only as text. Those fields appear first in the UI. [Validator](../stockinsight/research.py#L286) · [quote check](../stockinsight/research.py#L319) · [assessment rendering](../stockinsight/templates/desk.html#L54)

**Fix.** Link material assertions in the assessment and changes to typed claims, observations or calculation receipts. Check numerical assertions against their metric, period, units and source. Give readers the SEC financial metadata beside its bare numeric quotation. Preserve human review of interpretive support. The dividend example must remain unanswered or qualified.

### High · 2 · The investigator cannot truthfully record some missing inputs, or clear others once found

The same dividend case could not submit an honest partial answer. Revenue was available, but no tool could register the missing dividend and partial requires a service-issued gap. In a second MSFT run, an empty search created a gap, a mocked SEC capture succeeded and a second search returned the requested quarter. Both complete submissions were rejected, with and without the old gap. A partial submission succeeded with an open gap saying there were no eligible passages. Capture failures also share one preset cause and remedy across different source statuses. [Gap definitions](../stockinsight/bridge.py#L11) · [creation](../stockinsight/bridge.py#L155) · [validation](../stockinsight/research.py#L298) · [gap contract](stock-insight-v3/design/DATA_AND_TOOL_CONTRACTS.md#L126)

**Fix.** Support a scoped, receipt-linked gap for the specific missing metric, period or capability. Keep failed attempts in history and reconcile the open gap against later successful evidence. Derive final completeness from outstanding material gaps. Link a remedy or development proposal to unresolved gaps.

### High · 3 · A superseded value can be accepted as current

In a simulated SEC run without a historical cutoff, the worker read a quarterly value of 120. A correction to the same source and quarter reporting 95 was committed before submission. A brief calling 120 the latest value was accepted. Exact-ID lookup correctly preserves the old source, but submission checks its identity and bytes without reconciling a material correction already known at freeze time. This differs from an expired worker or an intervening case revision, both of which have working fences. [Exact retrieval](../stockinsight/evidence.py#L338) · [submission](../stockinsight/research.py#L312) · [information policy](stock-insight-v3/design/DATA_AND_TOOL_CONTRACTS.md#L50)

**Fix.** For a current-value claim, detect a superseding edition of the cited input at freeze time and require a reread or an explicit historical qualification. Unrelated acquisitions should still proceed and old citations must remain retrievable.

### High · 4 · Confirming one list’s candidate can relabel another list’s issuer

Source A staged a destructive NVDA replacement with a synthetic contract ID. Source B subsequently accepted MSFT with that ID. Confirming A changed B’s existing instrument from Microsoft, CIK `0000789019`, to NVIDIA, CIK `0001045810`. Its ID and both memberships survived, while B’s accepted snapshot still said MSFT. Existing cases can consequently display under the wrong company. The import-time conflict test predates confirmation. [Import](../stockinsight/universe.py#L442) · [confirmation](../stockinsight/universe.py#L526) · [shared row update](../stockinsight/universe.py#L313) · [existing test](../tests/test_insight_universe.py#L130)

**Fix.** Recheck contract, listing and issuer bindings across sources in the activation transaction. Reject or regenerate a stale candidate. Show the specific source and affected listings before confirmation. The current web card identifies only counts and a reason. [Candidate card](../stockinsight/templates/desk.html#L85) · [preview requirement](stock-insight-v3/design/WATCHLIST_SYNC.md#L75)

### High · 5 · Browser cookies leave private sessions exposed to other loopback ports

Both desks in the README use `127.0.0.1` and issue `insight_session` at path `/`. Browsers scope cookies by host and path across ports. Signing into the other instance replaces the first cookie, and a different service visited on the same loopback host can receive the bearer. Each instance does generate its own random token. Incoming Host, Origin and CSRF checks protect their respective operations but do not isolate cookie delivery. This is a source- and standards-based finding. No credential collection was attempted. [Authentication](../stockinsight/web.py#L25) · [Set-Cookie](../stockinsight/web.py#L97) · [two documented instances](../README.md#reproduce-the-public-data-check) · [RFC 6265 §8.5](https://www.rfc-editor.org/rfc/rfc6265#section-8.5)

**Fix.** Give each private instance an isolated browser credential boundary. Verify simultaneous ordinary and fixture sessions with a real browser cookie jar. A different cookie name alone still sends the bearer across ports on the same host.

### Medium · 6 · A duplicate continuation runs twice

After one accepted fixture question, two identical authenticated “Investigate again” POSTs both returned 303. Reopening the database showed revision 3, three jobs, three briefs and three inbox rows. The form omits an idempotency key and each continuation creates a fresh one. With billing enabled this could incur a second charge for one investigation. Initial question and accepted-result replays do deduplicate. [Form](../stockinsight/templates/desk.html#L82) · [route](../stockinsight/web.py#L205) · [job creation](../stockinsight/research.py#L133) · [initial POST test](../tests/test_insight_web.py#L128)

**Fix.** Bind the continuation form to a stable request key and expected base revision. Replaying it must return the original job. A fresh deliberate request may create a later revision.

### Medium · 7 · Keyword matching misclassifies questions in both modes

The fixture marked a question about FY26 third-quarter GAAP operating margin complete with a FY25 Q1-to-Q2 revenue answer and zero gaps. Its existing rejection test uses a shareholder-meeting question without a matching keyword. In the shared requirements logic, “Did quarterly revenue decline year over year?” requires both price and consensus, while “Did the shares rally after the filing?” requires neither. [Fixture gate and answer](../stockinsight/executor.py#L374) · [required checks](../stockinsight/research.py#L17) · [existing scope test](../tests/test_insight_executor.py#L100)

**Fix.** Limit fixture acceptance to the metric and periods the packet supports. Determine required evidence from the question’s actual premise and typed assertions. Cover both misclassifications.

### Medium · 8 · Watchlist validation rejects a real listing and can retain account-like source labels

A fresh instrument-only CSV containing fully specified NASDAQ common stock rows for `CASH` and `MSFT` rejected the entire snapshot. `CASH` is Pathward’s ticker. The parser applies forbidden report labels to values as well as restricting headers. Separately, CLI source IDs reject only whole-string account patterns, then persist the entire ID as an alias. Embedded account identifiers therefore escape the check by inspection. No personal data was used. [Instrument projection](../stockinsight/universe.py#L150) · [source identity](../stockinsight/universe.py#L258) · [Pathward filing](https://www.sec.gov/Archives/edgar/data/907471/000090747126000034/cash-20260630.htm)

**Fix.** Validate headers and listing values in context. Accept a resolved or fully specified CASH listing while continuing to reject account reports. Apply the embedded-identifier check consistently to user-provided source labels.

## Before proceeding

1. Close findings 1–3 on disposable, non-NVDA cases. Retain the correct MSFT calculation as a positive control. Reject or qualify the invented dividend, resolve the gap after acquisition, and reconcile a material pre-freeze correction while preserving all source editions.
2. Close findings 4–6 with a two-source identity regression, a two-instance browser check and replay of the same continuation form across restart. Verify original issuer identity, private session isolation, and one job/brief/inbox effect per user request.
3. Correct the fixture and watchlist scope errors in findings 7–8. Keep these cases beside the existing regressions and verify private Windows permissions for any intended custom workspace. Refresh the completion ledger to distinguish arithmetic, data acquisition, model execution and user review.
4. Keep authenticated model/provider acceptance open under the no-spend decision. Any later authorized trial should capture the accepted or blocked result, actual model/effort and usage, scoped tool receipts, exact sources and remaining gaps. The review ends at I1/I2.

The store, recording bridge and application-owned submission transaction support continued corrective development. The milestone has enough independent evidence to retain its architecture. Private normal use and expansion into I3 should wait for the in-scope fixes above.
