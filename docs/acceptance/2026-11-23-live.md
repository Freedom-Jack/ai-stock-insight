# 个人 Stock Insight 实时运行验收

2026-11-23，Windows，美东时间。前一次用真实 dot 做了历史财报回放。本次使用同一 dot 委派任务、已启用的正式 **Stock Insight** 插件、既有个人名单和当前公开来源。仓库只记录验证方法与汇总，个人案件号和账户计划 ID 可在各自界面查看。

## 日常入口与分工

| 谁运行 | 工作 | 结果在哪里 |
|---|---|---|
| 登录 Windows 的个人电脑 | Startup 快捷方式启动主仓库的个人工作台。采集器按各来源的频率保存证据，按已采用的目标决定是否派工，处理重试，并保留历史。TSMC 供应链监测复用 Stockwatch 模块。 | 双击仓库的 `Start-StockInsight.cmd`，打开 **Today**、**Events & monitoring** 或 **Goals**。报告的 Windows 通知指向本地案件。 |
| 现有 Work dot 的研究任务 | 用已连接的电脑和个人插件读待办、领取案件、阅读原文及提交引用。财务比较使用案件内已保存的数字。 | 原委派任务可回读结果，同一报告写入电脑。原任务名称中的 Replay 是首次历史测试留下的标题，连接目标由当前插件决定。 |
| Work 的定时服务 | 平台计划 **Personal 股票监测** 按纽约时区每小时第 50 分钟检查。电脑离线时跳过，无新材料时静默，每轮最多处理一项。现有研究目标的每日派工上限为 3。 | 平台计划和委派任务有各自的记录。主 dot 的消息投递与本机 Windows 通知有独立回执。 |

**下次登录的条件。** 已回读 Stock Insight 快捷方式，目标指向主仓库，Windows 没有为它设置禁用标记。验收时 ChatGPT 桌面已运行；其独立的 Windows 启动任务报告状态 1（`DisabledByUser`）。用户可到 **Windows 设置 → 应用 → 启动 → ChatGPT** 启用，或每次登录后手动打开 ChatGPT 并保持电脑连接。工作台可以先行采集并持久保存待办。[微软启动任务状态](https://learn.microsoft.com/en-us/uwp/api/windows.applicationmodel.startuptaskstate) · [Windows 启动应用设置](https://support.microsoft.com/en-us/windows/experience/startup-boot/configure-startup-applications-in-windows)

## 实际操作与结果

1. 确认个人库有 3 个有效标的和 1 项已采用目标。备份旧库，迁移后启用个人助手。个人插件限定为当前 Windows 用户的正式库。历史插件已从本机卸载，可按原清单重建验收环境。
2. 部署当前用户的登录启动项，以该入口实际启动并正常重启了个人工作台。认证访问 Today、监测、状态及已完成案件均返回 HTTP 200。重启前后原案仍有同一项已接受研究、同一原文引用及同一通知展示时间。测试未执行整机重启或用户注销。
3. 真实 dot 领取一项待办，读取保留的美联储日历并提交研究。本机确认 `fixture=false`、案件为 `accepted`、引用指向美联储官网。报告说明这条证据能确定会议安排，政策结果还需查后续声明。Windows 记录了该案通知的 `shown` 回执（00:29:25 EST）。上一轮的财报计算与同案追问可单独重现。[美联储会议日历](https://www.federalreserve.gov/monetarypolicy/fomccalendars.htm) · [历史财报及追问验收](2026-11-22-chat-work.md)
4. 重启后的监测记录显示 3 个标的都完成了美联储日历检查，其中 2 个有发行人专属来源，1 个匹配已审核的 TSMC 供应关系。第 3 个标的的市场日历可用，个股财报覆盖仍有限。TWSE 00:26 检查成功，USGS 的早期检查遇到来源生成时间领先本机，00:46:42 自动恢复成功并排定下一次检查。供应链共享采集对同一来源只维护一份检查记录。操作员对供应商影响作出的私有判断留在本机。
5. 平台查重、创建并回读了一个每小时的计划，归属原委派任务。00:31:02 预定时间过后，下次时间推进至 01:31:02，但查询返回的最后时间早于 00:31，运行详情和结果为空，投递状态为 `unknown`。这次用户授权的即时研究已有端到端回执。关闭原聊天后定时器自行领取、提交及转发至主 dot 的完整链路尚待独立回执。个人库的事件订阅数为 0；当前启用的是平台轮询。
6. 在同一计划中把条件检查切换为固定时间执行（`exact_schedule`），平台回读的首次触发为 00:50:00，以后每小时第 50 分钟执行，修改接口未提供更换收件线程的字段。触发前本机有 1 项已接受、2 项待领取。在 00:50 过后查询，平台显示下一次为 01:50、最后时间为 00:47:19，`last_run=null`、`latest_result=null`、`delivery_status=unknown`。00:52:20 和 00:53:58 两次读取个人库，仍有相同两项待办，均无领取时间。后台定时研究及主 dot 投递本轮未通过验收。账户侧应在原 dot 的 **Scheduled → Personal 股票监测** 查对应运行；本地报告和 Windows 通知已有各自的实证。[Work 定时任务说明](https://learn.chatgpt.com/docs/dots/tasks-and-memory)

## 修复与覆盖范围

- 个人插件只打开既有正式库；回放入口继续校验隔离模式。登录启动项使用当前用户加密的短期连接信息将交互启动器接回同一进程。日常使用只需开个人工作台。
- 符合美国市场条件但尚缺发行人 CIK 的标的可使用市场日历。发行人财报接入继续校验发行人身份和提供方所需配置。
- 地震原始观察和后续交易所公告在同一标的、同一目标下归入同一事件案件，保留各自的引用与版本。私有复核内容由本机处理。相同来源的健康检查同时用于监控界面、助手和目标报告。
- 遇到 USGS 的生成时间晚于本机收件时间，拒绝该版本，保留最后有效记录，将重试错开半分钟。正常地震采集仍为每五分钟，交易所公告每小时。回归测试覆盖未来时间、恢复、限流与重复来源。

完整运行 `python -B -m unittest discover -s tests -q`，共 263 项，261 项通过，2 项因当前环境未安装可选 Playwright 测试组而跳过。个人工作台的实际 HTTP 检查、真实 MCP 提交和 Windows 通知回执另行验收。
